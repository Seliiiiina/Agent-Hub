# Agent Hub 测试场景——辉瑞药企背景

状态：待执行的验收设计。以下以辉瑞药企工作背景构建虚构场景，全部文档、角色和规则均为合成测试材料，不代表辉瑞实际制度、系统或已部署能力，不构成法规或合规要求。

## 测试目标与前提

通过“内部培训 SOP 更新评审”验证从内部 Agent 推荐、工作流编排、用户确认到多 Agent 执行和结果审核的完整路径。标准场景资料完整，变化场景增加角色条件和缺失附件，验证 Hub 能否澄清输入、重新匹配并调整工作流。

测试前需确认 Registry 知识源可检索，所需功能 Agent 和业务 Agent 已部署且可调用。Active 只表示定义可发现，不代表运行可用。下列为预期行为，实际多 Agent 调用需通过运行记录验证，不以对话模拟替代。

## 共用背景与合成材料

假设辉瑞某内部培训协调团队需要评审一份行政培训管理 SOP 的修订草稿，了解变化、影响及需人工确认事项，并形成中文培训简报。此处不涉及患者数据、临床决策、药品不良事件、药品质量投诉或对外推广材料。

### 材料 A：SOP-TRAIN-DEMO v1（测试基线）

本文仅提供第 1 至第 4 节的完整测试文本，不代表真实 SOP。场景中明确以 v1 为旧版、v2 为待审核修订草稿。

| 章节 | 测试文本 |
| --- | --- |
| 第 1 节：适用范围 | 本流程适用于虚构团队 Alpha 的内部行政培训，参与角色包括团队成员、培训协调员及文档负责人。 |
| 第 2 节：培训安排 | 每月由培训协调员整理培训清单，通过人工邮件提醒相关成员。 |
| 第 3 节：完成确认 | 成员应在收到通知后 10 个工作日内完成培训，协调员每周整理完成情况。 |
| 第 4 节：记录与访问 | 完成记录保存于测试记录表，成员仅能查看本人记录，协调员仅能查看其获授权团队的记录。 |

### 材料 B：SOP-TRAIN-DEMO v2（待审核修订草稿）

| 章节 | 测试文本 |
| --- | --- |
| 第 1 节：适用范围 | 本流程适用于虚构团队 Alpha 的内部行政培训，参与角色包括团队成员、培训协调员及文档负责人。 |
| 第 2 节：培训安排 | 每两周由培训协调员整理培训清单，拟通过内部培训平台发送提醒，提醒内容由协调员审核。 |
| 第 3 节：完成确认 | 成员应在收到通知后 5 个工作日内完成培训，协调员每周整理完成情况。 |
| 第 4 节：记录与访问 | 完成记录拟保存于内部培训平台，成员仅能查看本人记录，协调员仅能查看其获授权团队的记录。 |

### 业务约束

- 评审目的：识别版本差异、潜在流程影响和待确认事项，供培训协调员与文档负责人讨论。
- 已知流程依赖：培训清单、提醒审核、完成情况记录及现有访问权限。未提供具体平台名称、接口、预算或上线日期。
- 交付要求：中文版本差异表、影响分析草稿及不超过 800 字的培训简报，证据表可另附。
- 所有内容仅为评审草稿，不批准 SOP、不发送提醒、不安排培训、不修改平台或记录。
- 不访问真实内部平台，不使用真实员工身份，不能声称修订已经生效或满足任何监管要求。

## 场景一：标准场景——SOP 修订到培训简报

### 可复制输入

将材料 A、材料 B 和业务约束与以下请求一起输入新会话。

> 我在辉瑞药企背景的合成测试中担任内部培训协调员。请比较 SOP-TRAIN-DEMO v1 与 v2 修订草稿，识别实质变化，评估对已给定角色和流程的影响，再生成一份给培训协调员和文档负责人审核的中文培训简报。每项变化与影响都应关联来源章节，区分直接观察到的变化和需要验证的推断。请优先推荐内部 Agent，解释推荐理由并展示多 Agent 工作流，等我确认后再执行。不要发送提醒、修改系统或宣称 SOP 已生效。

### 预期推荐与工作流

| 步骤 | 内部 Agent | 输入与任务 | 输出与交接 |
| --- | --- | --- | --- |
| 1 | Document Version Comparison Agent | 比较明确标注旧新顺序的两版文本 | 带版本和章节引用的差异清单，交给影响分析步骤 |
| 2 | Change Impact Analysis Agent | 使用基线、拟议变更、差异清单及已知依赖 | 角色和流程影响、待验证依赖及审核问题 |
| 3 | Business Report Draft Agent | 汇总差异及影响，按受众和篇幅成稿 | 培训简报草稿、证据引用及待确认项 |

Hub 应经 Finder 推荐，Workflow Builder 编排，用户确认后由 Executor 协调调用，最后由 Hub 汇总。上述方案为验收参考，依赖合理、覆盖要求的等价方案可接受。

### 操作步骤

1. 输入完整材料和请求，检查内部推荐及解释，保存 Finder 实际调用证据。
2. 检查工作流的 Agent、输入输出、顺序、权限及人工审核节点。
3. 回复“确认按此工作流处理提供的两版合成 SOP，只生成差异、影响分析和培训简报草稿，不访问或修改外部系统”。
4. 检查实际调用及中间结果交接，核对产物后接受结果或提出修改。

### 预期结果与通过标准

- 明确识别第 2 节安排频率、提醒渠道及审核要求，第 3 节 10 个工作日变为 5 个工作日，第 4 节拟议记录载体变化。
- 指出第 1 节范围及角色、第 3 节每周汇总频率、第 4 节访问权限规则保持一致，不编造变化。
- 使用 v1/v2 与章节引用，覆盖范围仅限提供的四节文本，不声称检查过完整正式 SOP 或附件。
- 将平台配置、提醒审核衔接和记录迁移等影响表述为待验证事项，不编造接口、负责人姓名、预算或上线日期。
- 简报为中文且符合篇幅，5 个工作日明确属于修订草稿中的拟议安排，不表述为辉瑞实际要求。
- 确认前无任务执行，确认后多个 Agent 实际调用可核查，无提醒发送或系统修改，交付后等待用户审核。

## 场景二：变化场景——角色条件与缺失附件触发流程调整

### 初始操作

在新会话中输入场景一全部材料与请求。等 Hub 展示工作流后，先不确认，追加下面的变化输入。

### 可复制变化输入

> 请替换材料 B 的第 3 节：完成周期按照“角色与周期映射附件 R”执行，协调员仍每周整理完成情况。其余章节不变。请新增一份按角色划分的培训需求和拟议验收标准草稿，纳入最终简报。附件 R 我还没有提供，请先告诉我缺什么，再推荐所需内部 Agent 并调整工作流，等我确认后执行。不能继续把 5 个工作日写成所有人的要求，也不要沿用已被替换的文本。

### 预期澄清与补充输入

Hub 应请求附件 R 的可读内容或明确的角色与周期规则。不能自行推断各角色周期，不能在缺失时声称完成依赖附件的分析。

评委在看到澄清后提供以下合成附件：

| 来源定位 | 角色 | 周期规则 |
| --- | --- | --- |
| 附件 R，第 R1 项 | 团队成员 | 收到通知后 5 个工作日内完成 |
| 附件 R，第 R2 项 | 培训协调员 | 收到通知后 3 个工作日内完成 |
| 附件 R，第 R3 项 | 文档负责人 | 仅审核通知内容，本次不要求参加该培训 |

补充说明：附件 R 仅属于本次合成 v2 修订草稿，未获正式批准。请基于更新后的材料继续设计方案。

### 预期更新后的工作流

| 步骤 | 内部 Agent | 变化后的任务 |
| --- | --- | --- |
| 1 | Document Version Comparison Agent | 比较 v1 与替换后的 v2，结合附件 R，标记旧版 v2 第 3 节已被替换 |
| 2 | Change Impact Analysis Agent | 分析角色差异对通知、完成情况统计和审核衔接的影响 |
| 3 | Requirements Analysis Agent | 基于角色规则与影响分析，生成需求和拟议验收标准，关联附件条目 |
| 4 | Business Report Draft Agent | 汇总差异、影响及角色化需求，形成更新的培训简报 |

### 人工确认示例

> 确认按更新后的工作流执行，使用替换后的 v2 和附件 R，只生成评审草稿。不发送通知、不安排培训、不修改系统或权限，未确认的依赖保留为问题。

### 预期结果与通过标准

- 缺少附件时最小必要澄清，不能编造附件内容或套用旧版 v2 的统一 5 日规则。
- 补充附件后，Finder 为新增需求草稿推荐内部 Requirements Analysis Agent，Workflow Builder 更新步骤、依赖与输入，并等待用户确认。
- 实际调用包含新增 Agent，运行记录体现更新后的材料传入后续步骤，不能仅口头称已更新流程。
- 正确区分成员 5 日、协调员 3 日及文档负责人仅审核且无需参训，引用 R1/R2/R3，不误称法规期限或已生效要求。
- 验收标准明确标记为提案，例如按角色显示对应周期、区分无需参训角色、保留每周汇总规则，不编造实际系统功能已上线。
- 当前访问权限保持不变，报告无真实员工信息或外部操作，不声称已批准培训要求。
