## 测试所需能力与数据

- 测试输入、字段规则及预期结果见 [02-测试场景](02-测试场景.md)，可直接复制共用材料，无需真实客户数据。
- 所需功能 Agent：Agent Finder、Workflow Builder、Agent Executor。Agent Creator 用于能力缺口路径，本次两个案例不以外部搜索或创建为前提。
- 所需业务 Agent：Document Version Comparison Agent、Change Impact Analysis Agent、Requirements Analysis Agent、Business Report Draft Agent。
- Agent Registry 知识源需要就绪且可检索，所有参与 Agent 的调用关系应实际验证。
- 本次案例只读取提供的材料并生成草稿，不要求业务系统写权限、邮件发送权限或真实 API 凭据。

## 最短运行步骤

1. 使用已获授权的评委账号打开入口并登录。
2. 新建会话，复制测试场景中的共用材料、业务约束和场景一输入。
3. 查看推荐及工作流，确认 Agent、输入、交付要求和权限范围。
4. 按文档中的确认示例执行，核对最终结果与通过标准。
5. 新建会话运行场景二，在初始工作流展示后追加变化输入，核查重新推荐和工作流调整，确认后执行。
6. 保存会话、结果及可访问的运行证据，记录实际通过情况。

## 如何确认实际运行

运行负责人应提供 Finder、Workflow Builder、Executor 和各业务 Agent 的调用记录，并能核查中间结果与最终产物。评委无需获得超出自身权限的管理日志，必要时由负责人提供脱敏导出或截图。只有对话中描述了执行过程，不能证明多个 Agent 被实际调用。

输出应为可审核草稿，Hub 应等待用户反馈，不声称已实施业务变更。若只具备模拟条件，需明确标注为流程演示，并在提交前解决可实际运行的入口要求。

## 访问失败处理

| 问题 | 检查与处理 |
| --- | --- |
| 无法打开或登录 | 核实链接、租户、账号、许可证及访问组，联系负责人 |
| 无法检索目录 | 检查知识源处理状态及检索权限，不编造推荐结果 |
| 子 Agent 不可调用 | 核查发布状态、调用配置、身份和权限，如实记录阻塞 |
| 所需业务数据无权限 | 不绕过访问控制，改用已提供的合成数据或按流程申请权限 |
