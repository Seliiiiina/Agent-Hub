## 评委复测步骤

以下步骤需在补齐入口、原始输入及实际调用方式后复核，尚未完成评委账号验收。

1. 使用已获授权的评委账号打开入口并登录，确认知识源及所需 Agent 可用。
2. 使用场景一原始会议材料，核对会议纪要和行动计划是否保留约定日期、负责人及未批准事项。
3. 核对内部邮件草稿和获准的测试收件人；连接授权与最终发送分别确认。发送后核查真实返回状态，不直接沿用历史收件人再次发送。
4. 在同一案例背景下提供场景二的文献延期更新，核查修订计划是否保留原截止日期并指出依赖冲突。
5. 将团队尚未决定的方案保留为待决问题，不自动调整日期或再次发信。
6. 保存实际调用方式、授权、结果和日志。若复测 Hub 自动编排，另行记录 Hub、Workflow Builder、Executor 及业务 Agent 的调用链。

## 如何确认实际运行

运行负责人应提供案例实际涉及的 Agent 调用记录、中间结果及最终产物。Hub 自动编排另行验收时，需要补充 Finder、Workflow Builder、Executor 和业务 Agent 的完整调用记录。评委无需获得超出自身权限的管理日志，必要时由负责人提供脱敏文字导出或运行记录。

会议纪要、计划和研究概念材料保持内部讨论草稿状态；邮件发送是否成功单独依据工具返回记录。当前两个业务案例已跑通，Hub 自动编排及评委账号访问验证仍待完成。

## 访问失败处理

| 问题 | 检查与处理 |
| --- | --- |
| 无法打开或登录 | 核实链接、租户、账号、许可证及访问组，联系负责人 |
| 无法检索目录 | 检查知识源处理状态及检索权限，不编造推荐结果 |
| 子 Agent 不可调用 | 核查发布状态、调用配置、身份和权限，如实记录阻塞 |
| 所需业务数据无权限 | 不绕过访问控制，改用已提供的合成数据或按流程申请权限 |
