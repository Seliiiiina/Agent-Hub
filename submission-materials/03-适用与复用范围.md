# Agent Hub 适用与复用范围

状态：已同步 Agent 部署、内部网页知识源及两个平台案例；试点人数和推广工作量待补。更新日期：2026-10-17。

## 适用团队与项目

| 团队或使用角色 | 代表任务 | 使用前提 |
| --- | --- | --- |
| 研究项目协作角色（本次案例） | 研究概念讨论纪要、行动计划、内部邮件及延期后的依赖冲突检查 | 提供会议记录、约定日期及业务边界；发送前核对收件人、连接授权和最终内容 |
| 产品与客户支持 | 反馈归纳、需求草稿、改进简报 | 有权使用反馈，具备业务口径与审核人 |
| 项目与运营团队 | 项目复盘、决策记录、交接材料 | 提供目标、实际结果、相关记录与交付要求 |
| 财务及分析角色 | 预算差异、数据质量审查、分析报告 | 提供授权数据、指标口径，必要计算工具已验证 |
| 开发与技术团队 | API 集成草稿、代码审查、测试草稿 | 提供代码与文档，明确运行环境及工具边界 |

GitHub 仓库中的 Agent 已全部在 Copilot Studio 配置部署，业务 Subagent 共 172 个。本次提交展示会议纪要与行动计划交付、文献延期后的计划修订两个业务案例，详见[测试场景](02-测试场景.md)。其他任务的运行效果需分别验证，不能由部署数量推定。

Hub 统一入口和自动编排仍属于待验证设计。场景二确认后的纪要、计划和邮件联动更新尚未执行。

## 数据源范围

- 当前知识源已接入公司内部网页资料，具体网页实例：【待填写】。
- 本次案例使用会议任务、行动计划和延期更新；完整原始输入待补，见[测试场景](02-测试场景.md)。目前不将内部网页检索列为这两个案例已经验证的步骤。
- Agent Registry 用于发现、分类、比较和推荐，不是业务事实数据源。
- Finder 的内部目录知识源为 SharePoint `Agent-Registry.md`。
- 场景一使用 Work IQ Mail MCP 授权连接，历史交付记录为 Microsoft 365 邮件发送成功。
- 其他业务系统和代码仓库的连接情况需逐项记录，不从 Agent 已部署推定工具全部可用。
- 不默认具备实时查询、全量检索、外部系统写入或跨会话记忆能力。

## 可复用内容与配置要求

| 内容 | 可复用部分 | 推广时需修改或配置 |
| --- | --- | --- |
| Hub 入口 | 需求澄清、路由、推荐解释、结果汇总 | 名称、欢迎语、业务术语、支持渠道 |
| 功能 Agent | 发现、编排、执行、能力缺口处理的职责划分 | 实际调用关系、知识源、执行环境与返回契约 |
| Agent Registry | 分类、能力标签、状态和权限字段 | 公司内部 Agent 清单、来源、状态、权限及更新时间 |
| 业务 Agent | 已适配任务的指令与输出结构 | 团队术语、模板、业务规则、输入要求 |
| 数据和工具 | 数据源与工具接入方式 | 数据地址、连接身份、访问范围、环境与 DLP 配置 |
| 工作流 | 已验证的步骤与交接设计 | 数据源、范围、审核节点和每一步的运行可用性 |

## 复用与推广步骤

1. 确认团队需求与数据边界，先检查公司内部已有能力及可组合能力。
2. 更新 Registry 并部署所需 Agent，配置知识源、工具及用户身份。
3. 调整业务规则和输出模板，指定业务审核人与技术维护人。
4. 使用合成或脱敏数据完成标准、变化和权限测试。
5. 限定范围试用，记录问题后再决定推广。

## 不适用范围与后续扩展

不适合在缺少授权、必要数据、工具或审核人的条件下直接执行。不能将草稿作为业务审批、法律或合规结论，不能承诺未验证的跨平台调度或无人值守运行。

在当前部署基础上，对接公司其他 Agent 目录、跨团队共享、反馈驱动推荐、工作流模板、建设维护建议及进度查询属于后续扩展，需与平台实际能力和管理要求对齐。
