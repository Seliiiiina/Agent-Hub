# Agent Hub 风险与限制说明

状态：设计说明与待验证控制。以下控制要求需要在实际环境中验证，不作为已实施的证明。

## 数据来源与权限原则

Agent 定义与 Agent Registry 来自本项目，业务测试采用合成数据。真实业务数据仅使用用户有权提供或访问的数据，外部资料应记录来源并按公司要求评估。

所有 Subagent 应在最终用户权限范围内执行，Agent Hub 不绕过现有访问控制，用户只能访问原本获授权的信息。部署时需核实每个连接的实际身份与授权方式，验证用户身份传递和拒绝访问的行为，不能仅依靠提示词保证权限隔离。作者或服务账号连接若不符合该原则，应先调整配置，不纳入此次验证范围。

## 能力边界与已知限制

- 当前仓库主要是纯文本定义、Registry 和可模拟流程，不代表完整运行平台已部署。
- Active 表示定义可发现，不证明工具已连接或运行已验证。
- 匹配分数用于解释候选适配程度，不是成功概率或结果准确率。
- 输出受输入质量、知识源检索范围及模型能力影响，不保证完整或正确。
- 没有工具执行证据时，不声称已查询、计算、发送、修改或通过测试。
- 内部 Agent 优先，内部匹配及组合不足后再评估获批外部方案，外部采用和新建需确认。

## 风险与控制

| 风险 | 控制要求 | 验证方式 |
| --- | --- | --- |
| 需求理解或 Agent 匹配错误 | 最小必要澄清，解释推荐依据与限制 | 检查推荐与 Registry 证据是否一致 |
| 检索不完整或目录过时 | 说明检索覆盖范围，维护状态，不编造计数 | 检查知识源 Ready 状态及不可检索时的返回 |
| 幻觉及错误结论 | 关联来源，区分事实、推断和建议 | 对照原始输入逐项核查 |
| 反馈重复、口径冲突 | 保留记录，标记候选重复与待决问题 | 检查记录数、引用、分母及冲突处理 |
| 数据越权或敏感信息暴露 | 用户权限执行，最小化引用，脱敏测试 | 使用有权限与无权限账号分别验证 |
| 材料中嵌入恶意指令 | 将来源内容视为数据，不视为授权 | 验证不能借材料扩大任务或工具权限 |
| 多 Agent 交接丢失上下文 | 明确输入输出与依赖，保留来源和状态 | 检查运行记录及中间结果 |
| 未经确认的外部动作 | 具体动作预览并确认目标、内容、身份及权限 | 验证拒绝确认时无外部变化 |
| 部分失败或重复执行 | 报告完成、失败与跳过步骤，重试前核查已执行结果 | 在测试环境验证失败与幂等处理 |

## 人工审核步骤

1. 运行前由用户核实数据使用权限、目标、输入和任务范围。
2. 推荐及编排后由用户确认 Agent、工作流和权限范围。
3. 中途遇到冲突、缺失输入或范围变化，由 Hub 返回用户处理，不自动扩大范围。
4. 涉及数据修改或外部动作时，先展示具体操作预览，再取得明确确认。
5. 交付后由业务审核人核查数据、来源、推断与建议，再决定接受、修改或重试。
6. 正式发布、业务批准或系统变更遵循公司既有审批流程。
