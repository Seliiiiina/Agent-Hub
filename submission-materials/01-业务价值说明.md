## 核心价值主张

**Agent Hub：让业务需求找到合适的 AI 能力，让已有投入持续产生价值。**

把企业不断增长的 Agent 资源，转化为员工能够找到、理解并用于完成工作的业务能力。

## 业务问题与解决思路

随着企业 Agent 数量增长，员工寻找、选择和组合 Agent 的成本也随之增加。团队已有的能力难以被充分发现，相似需求还可能引发重复建设。

Agent Hub 从用户的业务需求出发，帮助用户明确任务、发现并比较合适的 Agent，在用户确认后组织任务执行。遇到能力缺口时，优先评估公司内部已有能力的组合，内部能力仍无法满足需求时，再评估经公司批准的外部方案能否复用或改造，必要时考虑新建。

用户无需提前了解 Agent 名称、技术实现或调用方式。Hub 的设计路径为：需求理解 → 发现与匹配 → 推荐与确认 → 必要时编排工作流 → 授权执行 → 结果审核。

## 三层价值

| 受益对象 | 预期价值 | 后续验证方向 |
| --- | --- | --- |
| 员工 | 降低寻找、理解和使用 Agent 的门槛，缩短从提出需求到获得可用结果的过程 | 匹配耗时、人工投入时间、结果可用率、返工次数 |
| 团队 | 扩大已有 Agent 的使用与复用，减少相似能力的重复建设，改善多 Agent 协作 | 复用次数、跨团队使用案例、避免重复建设的案例、新场景配置成本 |
| 企业 | 为后续能力建设提供依据，提高 Agent 投入的使用效益 | 使用率、能力缺口记录、复用与新建决策案例、经验证的收益 |

## 关键价值支撑

- 找到适合任务的能力：结合能力、业务领域、输入输出兼容性、可用性和权限进行匹配，解释推荐理由。
- 组织复杂任务：明确多个 Agent 的分工、执行顺序、依赖和输入输出，减少用户手工衔接。
- 优先复用内部能力：先使用公司内部 Agent，再评估内部 Agent 的组合，仍无法满足需求时才评估获批的外部方案，必要时提出新建方案。
- 保持过程可控：分开推荐、规划和执行，明确授权范围，并由用户审核结果。

## 内部 Agent 优先原则

1. 优先在公司内部发现并匹配已有 Agent。
2. 没有单个内部 Agent 能够满足需求时，评估多个内部 Agent 能否组合完成任务。
3. 确认内部没有合适能力，且无法通过组合满足需求后，再评估经公司批准的外部方案能否复用或改造。
4. 必要时提出新 Agent 的建设方案，由用户确认后推进。

## 权限与访问控制原则

- 所有 Subagent 均在最终用户的权限范围内执行。
- Agent Hub 不绕过现有访问控制。
- 用户只能访问其原本已获授权查看的信息。
- 使用 Hub 或调用 Subagent 不会扩大用户的数据访问权限。

具体连接身份及权限隔离的验证记录待补，见[风险与限制说明](04-风险与限制说明.md)。

## 后续扩展方向

以下方向分别保留为扩展设想，尚不代表已实现能力。

### 1. 对接公司 Agent 目录，补充统一管理能力

- 在当前 Copilot Studio 部署基础上，对接公司其他 Agent 目录，补充能力描述、可用状态和访问权限。
- 在平台已有的管理机制和权限体系下，提供统一发现与使用入口，协调不同 Agent 的协作。
- 逐步了解哪些 Agent 被使用、哪些能力可以复用，以及哪些需求仍存在能力缺口，提高内部资源利用效率。
- 接入范围、调用方式和管理权限需要与公司平台的实际能力对齐。

### 2. 跨团队的 Agent 共享与复用

- 帮助员工发现其他团队可共享的 Agent，了解适用场景、使用条件和负责人。
- 减少团队之间重复寻找和建设相似能力的成本。
- 共享遵循现有访问权限和共享规则，发现 Agent 不代表获得访问或执行权限。

### 3. 基于使用反馈持续优化推荐

- 在能力匹配基础上，逐步引入任务完成情况、用户评价和结果采纳情况。
- 同时参考能力描述与实际使用表现，帮助用户选择适合当前场景的 Agent。
- 信息收集、保存和使用遵循公司的数据与隐私管理要求，推荐改进效果需要实际验证。

### 4. 高频工作流沉淀为可复用模板

- 将经过验证的多 Agent 流程沉淀为模板，例如数据核对、差异分析和报告草拟。
- 明确必要输入、执行步骤、Agent 分工、输出要求和人工审核节点。
- 其他团队确认适用性并调整数据源、业务口径和权限配置后，可以复用已有流程。
- 模板复用仍需核实 Agent 的当前可用性，并遵循任务授权要求。

### 5. 为 Agent 建设和维护提供依据

- 在公司允许的数据记录范围内，汇总无法匹配的需求、频繁失败的步骤和用户反馈。
- 帮助平台负责人识别能力缺口、功能重叠及需要维护的 Agent。
- 为新增、整合、更新或下线提供证据和建议，具体决定仍由负责人审核。

### 6. 任务进度与执行记录查询

- 支持用户在权限范围内查看当前进度、已完成步骤、失败原因和待处理事项。
- 降低长时间或跨多个 Agent 任务的跟进成本，支持问题排查和结果追溯。
- 记录的可见范围和保存期限遵循公司平台管理要求。
- 查询进度本身不触发重试或继续执行。
